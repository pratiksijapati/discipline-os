# Deploying Discipline OS

Three free services, set up in this order (each one needs an address from the one before):

| Part | Service | What runs there |
|---|---|---|
| Database | **Neon** | PostgreSQL |
| API | **Render** | Django + gunicorn (`render.yaml`) |
| App | **Vercel** | The React PWA (`frontend/vercel.json`) |
| Reminders | **cron-job.org** | Calls the API once a minute to send due reminders |

Render and Vercel deploy from a Git repository, so the code has to be on GitHub (a **private** repo is fine).

---

## 1. Neon — database

1. Sign up at neon.tech → **New project** → name `discipline-os`, region closest to you (e.g. *AWS Asia Pacific (Singapore)*), Postgres 17.
2. On the project dashboard → **Connect** → turn **Connection pooling ON** → copy the connection string.
   It looks like `postgresql://USER:PASSWORD@ep-xxx-pooler.REGION.aws.neon.tech/neondb?sslmode=require`.
3. Keep it somewhere private for step 2. It contains the database password — never commit it.

## 2. Render — API

1. Sign up at render.com with GitHub → **New → Blueprint** → pick the repo. Render reads `render.yaml`.
2. It asks for the values marked *sync: false*:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `CORS_ALLOWED_ORIGINS` | `https://placeholder.vercel.app` for now (fixed in step 4) |
   | `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | copy both from `backend/.env` on your laptop |
   | `VAPID_SUBJECT` | `mailto:` + your own email |

   `SECRET_KEY` and `REMINDER_CRON_SECRET` are generated by Render automatically.
3. **Apply**. The first build installs packages, collects static files and creates all tables in Neon (~3–5 min).
4. Open `https://<your-service>.onrender.com/api/health/` → should show `{"status":"ok","database":"ok"}`.

**Admin user** (the free plan has no shell, so run this on your laptop, pointed at Neon):

```powershell
cd "C:\My daily schedule\discipline-os\backend"
$env:DATABASE_URL = "<the Neon string>"
.venv\Scripts\python.exe manage.py createsuperuser
Remove-Item Env:DATABASE_URL
```

## 3. Vercel — app

1. Sign up at vercel.com with GitHub → **Add New → Project** → pick the repo.
2. **Root Directory**: `frontend` (framework *Vite* is detected).
3. **Environment Variables**: `VITE_API_URL` = `https://<your-service>.onrender.com/api`
4. **Deploy**. You get an address like `https://discipline-os.vercel.app`.

## 4. Connect app ↔ API

Render → your service → **Environment** → set `CORS_ALLOWED_ORIGINS` to the exact Vercel address
(`https://discipline-os.vercel.app`, no trailing slash) → **Save** (it redeploys).

Then open the Vercel address on your phone, create your account, and **Add to Home Screen**.

## 5. cron-job.org — reminders

Render's free plan has no background worker, so an outside timer triggers reminders.

1. Render → **Environment** → reveal and copy `REMINDER_CRON_SECRET`.
2. cron-job.org → **Create cronjob**:
   - URL: `https://<your-service>.onrender.com/api/notifications/run/`
   - Schedule: every 1 minute
   - Advanced → Request method **POST**, header `X-Cron-Secret: <the secret>`
3. Save, then check the job's history shows **200**.

---

## Good to know (free-plan limits)

- **Render sleeps** after 15 minutes without requests; the first request then takes ~1 minute.
  The minute-by-minute cron keeps it awake, and one always-on service fits in Render's free monthly hours.
- **Neon** pauses the database when idle. The cron keeps it awake too, which uses Neon's free compute allowance.
  After the first week, check **Neon → Usage**. If it's getting close, set the cron to run only during your
  waking hours (cron-job.org lets you pick hours) — reminders outside those hours would then not send.
- **Updates**: every push to the main branch redeploys both Render and Vercel. Installed phones show
  "Update available" in the app.
- **Camera** (wake-up challenge) and **push** both need https — they work on the Vercel address, not on a
  plain `http://` LAN address.
